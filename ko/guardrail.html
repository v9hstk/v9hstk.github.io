Guardrail: 제1원칙에서 출발한 시스템 트레이딩 인프라

Single-family office · 멀티에이전트 아키텍처 · 리스크 엔지니어링 · AI 행동 분석 · 인프라 2025–현재

요약

Guardrail은 디지털 자산, 경성 원자재, 부동산, 프론티어 기술에 걸쳐 자율 자본 배분 시스템을 운영하는 single-family office입니다. 자기자본만 — 투자자·LP·클라이언트·환매 게이트 없음. 이 포트폴리오 사이트에서는 Hashstack·Parashar 옆의 금융 사이드 프로젝트로도 읽힙니다 — 콜드 아웃리치의 주력이 아닙니다.

저는 그 자세를 실제화하는 트레이딩 인프라 스택을 구축합니다 — Redis 이벤트 버스로 오케스트레이터가 조율하는 9개 전문 서브에이전트 멀티에이전트 실행 시스템, 7-check 프로그램 리스크 플레인, AI 행동 분석 엔진, 43-task 배포 DAG를 관리하는 빌드 오케스트레이터. guardrail.fund 공개 포지셔닝: from signal to settlement — no human in the loop.

라이브 스택의 베뉴 포커스는 파생(Hyperliquid)과 예측 시장(Polymarket)을 포함하며, 더 넓은 SFO mandate 안에 있습니다. 인프라는 라이브입니다. 자본은 100% 자기자본 — 제3자 LP 자본 없음.

모든 결정을 관통하는 두 원칙: 리스크는 대시보드가 아니라 게이트, 그리고 인간은 가장 약한 고리 — 캐주얼 개입 지점은 모두 제거해야 할 실패 모드.

현재 상태

1. Mandate (공개 포지셔닝)

guardrail.fund에 따르면 배분은 네 버티컬 — 디지털 자산, 귀금속, 부동산, 기술(헬스텍, 보험, 방산, 항공우주, 바이오텍, 양자) — 에 걸쳐 있습니다. 운영 테제는 하드머니 희소성(BTC + XAU), 프로그래머블 결제, 실물 실수익 부동산, 집중 딥테크 베트를 포함합니다.

이 케이스 스터디는 외부 자본 피치가 아닙니다. 자기자본 배분 뒤의 시스템 트레이딩 인프라 — 리스크·저널링·행동 감독이 소프트웨어로 강제되는 방식 — 을 문서화합니다.

2. 문제: 대부분 트레이더가 지는 이유

리테일·소규모 운영자 트레이더는 전략과 무관한 세 이유로 실패합니다:

체계적 저널링 없음. 의사결정을 충분히 세분화해 추적하지 않아 무엇이 작동하는지 식별하지 못합니다. 셋업 유형·타임프레임·레짐별 승률을 모르는 트레이더는 자신의 엣지를 추측하는 것입니다.

실시간 리스크 강제 없음. 리스크 규칙은 종이에 있고 코드에 없습니다. 수동으로 확인할 때만 발동하는 드로다운 한도는 한도가 아니라 제안입니다.

감정 오버라이드. 규율은 스트레스 하에서 — 체계적·예측 가능·측정 가능하게 — 저하됩니다. 가장 건너뛰기 어려운 트레이드는 손실 후 복수 트레이드입니다.

터미널은 실행 루프에서 캐주얼 인간 오버라이드를 제거하고 판단 호출을 프로그램 제약으로 바꿔 세 문제를 모두 해결합니다. 시스템은 규율을 조언하지 않습니다 — 강제합니다.

3. 멀티에이전트 아키텍처

시스템은 Redis pub/sub 이벤트 버스 위 오케스트레이터가 조율하는 9개 전문 서브에이전트로 돌아갑니다. 각 에이전트는 한 도메인을 소유하고, 타입이 있는 이벤트를 발행·소비합니다. 어떤 에이전트도 전역 상태를 갖지 않습니다 — 조율은 버스를 통해.

왜 모놀리스가 아니라 에이전트인가

각 에이전트는 독립적으로 실패할 수 있습니다. Exchange가 내려가도 Risk는 비활성화되지 않습니다. Journal 오프라인은 포지션 모니터링을 막지 않습니다. Attention 실패는 인사이트 품질을 떨어뜨리지만 실행을 막지 않습니다. 연쇄 실패가 자본 손실을 의미할 때 장애 격리가 중요합니다.

이벤트 버스 설계

이벤트는 타입이 있고(POSITION_OPENED, RISK_CHECK_FAILED, ANOMALY_DETECTED, DECAY_ALERT), 타임스탬프·소스 태그가 붙습니다. 오케스트레이터가 교차 에이전트 응답을 라우팅 — 예: POSITION_LIMIT_BREACH → Exchange 축소; TILT_DETECTED → 세션 일시정지 에스컬레이션.

4. AI 레이어: Attention + Summary

대부분 트레이딩 시스템은 AI를 시그널 생성기로 취급합니다. Attention 에이전트는 트레이드 아이디어를 만들지 않습니다 — 운영자를 감시합니다.

운영자 자신의 Journal 베이스라인 대비 라이브 행동을 점수화합니다: 손실 후 사이징 드리프트, 진입 빈도 급증, 홀드 타임 압축, 레짐 불일치, 확신–결과 괴리, 세션 패턴 변화. 편차는 타입 버스 이벤트를 방출합니다. Haiku가 실시간 점수화; Sonnet은 이상이 확인되고 맥락이 요청될 때만 내러티브 설명을 생성합니다.

Summary 에이전트는 교차 에이전트 상태를 세션 리포트, 성과 귀속, 행동 다이제스트, 포트폴리오 리스크 스냅샷으로 종합합니다 — 두 번째 리서치 엔진이 아니라 집합 에이전트 상태의 읽기 레이어.

5. 7-검사 리스크 플레인

리스크는 대시보드가 아니라 게이트입니다. 모든 트레이드는 실행 전 일곱 검사를 통과합니다. 하나라도 실패하면 차단. 플레인은 캐주얼 우회 없음으로 설계; 예외가 있다면 감사 가능한 경로 — 순간 오버라이드 버튼이 아닙니다.

Kelly 입력은 셋업 유형별 운영자 Journal 이력에서 옵니다. Portfolio 에이전트의 Monte Carlo는 새 포지션 승인 전 북 수준 테일 리스크를 모델링 — 개별로는 안전하지만 하나의 매크로 팩터에 함께 터지는 다섯 레그를 잡습니다.

6. 빌드 오케스트레이터: 43-Task 배포 DAG

개발·배포는 43-task DAG를 사용합니다: 의존성 해석, API 레이트 리밋 시 자동 재개, 노드별 체크포인트, 멀티모델 라우팅(태스크 유형별 Haiku / Sonnet / Opus), 에이전트별 롤백으로 실패한 배포가 전체 시스템을 내리지 않게.

7. Wallet Decay 진단

펀딩·수수료·슬리피지·반올림은 트레이드별로 노이즈처럼 보이는 느린 출혈을 만듭니다. Wallet Decay 에이전트는 15분마다 기대 대 실제 잔고를 확인하고 침식 원인을 펀딩·수수료·슬리피지·반올림에 귀속 — 보이지 않는 자본 감쇠를 보이게 합니다.

8. Auto-Journal: 29 필드

시스템은 거래소 데이터에서 29필드 중 22를 자동 채우고, 사전 4·사후 3 수동 입력을 남깁니다(22 + 4 + 3 = 29). Attention 필드와 TradingView 차트 링크는 오버레이 — 저널을 33으로 부풀리는 가산 카운트가 아닙니다.

절대 달러 금액은 표시하지 않습니다 — 퍼센트, ROE, R-배수만. 예측 시장에서는 Calibration Score가 명시된 확신이 시간에 걸쳐 결과와 얼마나 맞는지 추적합니다. 공개 예측시장 터미널에서 1급 지표로 다루는 경우는 드뭅니다.

9. 4계층 분리

엄격한 하향 전용 의존성:

  • Orchestrator — 에이전트 조율, 이벤트 라우팅, 워크플로
  • Integrity — 해시 체인 감사 로그, dead-man switch, kill switch
  • Observability — BetterStack, Retool, Summary 에이전트
  • Security — 읽기 전용 키, 네임스페이스 이벤트, 에이전트별 권한

모든 결정과 리스크 검사는 append-only SHA-256 해시 체인 로그에 남습니다. Kill switch(수동 flatten)와 dead-man switch(하트비트 누락 → safe mode)는 분리되어 하나의 실패 모드가 두 보호를 모두 지우지 못하게 합니다.

10. 복리 이점

11. QA — 목표 운영 규율

목표 주기(모든 관행이 이미 매월 의례화되었다는 주장이 아님): 배포당 단위+통합 테스트, 릴리스 전 회귀 스위트, 카오스 엔지니어링(목표 월간), 침투 테스트(목표 분기), GitHub Actions를 통한 에이전트별 롤백 CI/CD.

12. 핵심 요점

포지셔닝: Guardrail은 자기자본만의 SFO — 클라이언트 펀드·LP 비히클이 아님. 케이스 스터디는 자율 배분을 강제 가능하게 만드는 인프라를 보여줍니다.

리스크 엔지니어링: 리스크 대시보드는 피해를 보고합니다. 리스크 게이트는 예방합니다. 캐주얼 오버라이드는 게이트를 제안함으로 만듭니다.

AI: Attention은 시장이 아니라 트레이더를 모니터링합니다. 알파 손실은 종종 스트레스 하에서 잘못 실행된 좋은 전략에서 옵니다.

도메인 폭: DeFi 프로토콜 제품 작업을 출시한 같은 사람이 시스템 트레이딩 인프라도 구축 — 다른 도메인, 같은 “리스크가 인터페이스” 본능.
